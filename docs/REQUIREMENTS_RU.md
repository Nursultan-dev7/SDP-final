# Проверка требований Final Project

Проверены требования из исходного PDF, дополнительные условия пользователя и код репозитория Nursultan-dev7/SDP-final. Изменения оформляются отдельной веткой и pull request; исходная история сохранена.

| Требование | Состояние |
| --- | --- |
| Не менее 6 разных рабочих паттернов | Builder, Strategy, Decorator, Adapter, Observer, Facade участвуют в одном transfer lifecycle |
| Хотя бы один паттерн каждого типа | Creational: Builder; structural: Adapter/Decorator/Facade; behavioral: Strategy/Observer |
| Шесть пакетов паттернов | wallet.builder, wallet.strategy, wallet.decorator, wallet.adapter, wallet.observer, wallet.facade |
| Единственный класс вне этих пакетов — Main | src/wallet/Main.java: запуск GUI и проверка всех паттернов через --test |
| Правильная иерархия файлов | Каждый самостоятельный класс/интерфейс в отдельном одноимённом файле; роли паттернов разделены по соответствующим папкам |
| Clean code / SOLID / KISS / DRY | Ответственности разделены; зависимости передаются через интерфейсы; правила Transaction централизованы; run/test используют общую сборку |
| Каждый студент реализует минимум 2 паттерна | Требует подтверждения личным кодом и реальными коммитами; рефакторинг не подтверждает вклад всех троих |
| Git с историей всех участников | Исходный коммит сохранён, ветка изменений загружена; наличие реального вклада каждого проверяется отдельно |
| PDF: Intro, Body, Conclusion, Further work | Есть в обновлённом отчёте на 10 страниц |
| Java-код, скриншоты, UML | В PDF; полный код, тесты и исходники UML включены в репозиторий и ZIP |
| PDF и исходники ZIP | Обновлены под текущую структуру; загрузка в Moodle выполняется студентами |
| Каждый студент сдаёт вовремя | Студенты сдают отдельно; календарная дата в исходном PDF не указана |

## Исправления

- Классы перенесены из единого wallet в шесть пакетов. Builder, стратегии, component и decorator теперь отдельные файлы. Сборка и тесты запускаются через wallet.Main.
- Инварианты Transaction проверяются каноническим конструктором, поэтому их нельзя обойти прямым созданием record: проверяются адреса, ID, знаки сумм, точность и диапазон minor units. Builder повторно использует эти правила.
- Ошибка одного Observer после фиксации блока больше не прерывает доставку другим подписчикам; ошибка логируется.
- Авторизация отделена интерфейсом TransferAuthenticator, сеть — WalletNetwork. UI не дублирует комиссии и списание.
- Добавлены проверки истечения кода ровно через 120 секунд, замены review, replay, округления/диапазона сумм, порядка по комиссии и отказов подписчика.
- Обновлены build/run/test, UML, отчёт, исходный ZIP и материалы защиты. Проверка иерархии сверяет и исходники, и собранный JAR, исключая оставшиеся старые классы.
